## 2. Boundaries
| Component | Owns | Never does |
|---|---|---|
| **web/** | The editor (Y.Doc in the browser, selection, undo, inline editing, awareness rendering), the section registry, rendering published sites, host → slug routing | Touch the DB, Redis or Blob directly; decide what gets published |
| **api/** | Auth, membership, the durable update log, compaction and export (pycrdt), publish validation, stream fan-out, uploads, invites, billing | Render HTML; hold WebSockets; keep a document in memory between requests |
| **Postgres** | Everything durable: updates, snapshots, publications, members | Fan-out timing |
| **Redis (v2)** | Per-site stream for updates + awareness — *fast, disposable, capped* | Be the source of truth for a document |
| **Blob** | Image bytes | Anything else |
| **Section registry** (`web/src/sections`) | The one definition of what a section is: schema, defaults, component, thumbnail | Diverge from `api/app/sections.py` (hand-mirrored; the publish test catches drift) |

Contract: `api/openapi.json` (generated by FastAPI) → `web/src/lib/api-types.ts` via `pnpm gen:api`. The web client (`web/src/lib/api.ts`) is a typed `fetch` that forwards cookies and trusts only the `{ error: { code, message } }` envelope.

## 5. Deployment topology
- Two Vercel projects per repo (as Tripsmith / Frontrow): `pagecraft` (root `web/`) and `pagecraft-api` (root `api/`, FastAPI preset, `bom1`). `web/next.config.ts` rewrites `/api/:path*` → `API_URL`; cookies are first-party; no CORS.
- Domains on the `pagecraft` project: `pagecraft.virajdomadia.com` and the wildcard `*.pagecraft.virajdomadia.com` (requires `virajdomadia.com` on Vercel DNS — added when the portfolio domain moves; `/s/{slug}` works before that). Middleware rewrites the host.
- SSE route sets `maxDuration: 300` in `api/vercel.json` (v2); every other route 30 s. Publish and compaction stay well under.
- Neon: one project, `main` = production, a `dev` branch for local. Upstash (v2): one Redis, region Mumbai. Blob store on the `pagecraft-api` project. Razorpay webhook (v3) → `https://pagecraft.virajdomadia.com/api/webhooks/razorpay`.
- Previews: Vercel previews per PR for `web/` pointed at the production API (API previews are SSO-gated).
- CI (GitHub Actions): `web` = pnpm typecheck + build; `api` = ruff + pytest with `postgres:17` (and `redis:7` from v2). That is all.

## 6. Request paths worth drawing
**Edit:** keystroke → `Y.Text.insert` → local render (0 ms) → queue → 300 ms → `POST /api/sites/7/updates` → rewrite → FastAPI → `sites` row lock → `INSERT site_updates` (→ v2 `XADD`) → `{ seq }`; every 50th → pycrdt compaction.
**Publish:** `POST /api/sites/7/publish` → compaction → pycrdt export → pydantic validation → `INSERT publications` → `POST web/api/revalidate` → visitor's next request re-renders `/s/kaapi-corner`.
**Visit:** `kaapi-corner.pagecraft.virajdomadia.com` → middleware rewrite `/s/kaapi-corner` → ISR page (tag `site:kaapi-corner`) → `GET API/public/sites/kaapi-corner` (on miss) → `<SiteRenderer>`.
**Live (v2):** tab B `EventSource` → FastAPI generator → `XREAD BLOCK 1000` → tab A's `XADD` wakes it → `event: update` → `Y.applyUpdate` in B.

## 7. Security notes (the short list)
Cookie session HttpOnly + SameSite=Lax; argon2 passwords; membership check on every `/sites/{id}/*` route (404, not 403); update bodies capped at 256 KB and 200 updates per request; uploads type-sniffed and size-capped; published content validated server-side (no raw HTML in any field — text only, links `http(s)`/`#`/`mailto:`/`tel:` only); revalidate hook and Razorpay webhook secret-checked, webhook event ids deduped; `/public/*/submissions` and `/views` rate-limited per IP with a honeypot; no PII in logs.
